# نُور — نظام الحياة الشخصي

تطبيق ويب شخصي **أحادي المستخدم** لإدارة الحياة: مهام يومية، مؤقت تركيز (بومودورو)،
تدوين شامل، مشاريع، إحصائيات، نظرة، وأرشيف. واجهة عربية RTL بالكامل.

---

## بوابة الدخول (أحادي المستخدم)

النسخة المنشورة على GitHub Pages محميّة بـ**رمز دخول**. لا تُحمَّل الواجهة ولا البيانات
قبل إدخال الرمز الصحيح. تُخزَّن الإذنة في `sessionStorage` فقط، فتنتهي بغلق التبويب.

- الرمز الحالي: **`N0or-7kq9-Xz`**
- تغيير الرمز: ولّد تجزئة جديدة ثم بدّلها في `js/lock.js` → `CFG.passSha256`:

  ```bash
  node -e "console.log(require('crypto').createHash('sha-256').update('رمزك الجديد','utf8').digest('hex'))"
  ```

- تعطيل البوابة كلياً: اضبط `CFG.enabled = false` في `js/lock.js`.
- البيانات المبدئية تُنسَخ إلى `localStorage` من `data/seed.json` عند أول دخول فقط
  (إذا كان التخزين فارغاً). أي تعديل تجريه لاحقاً يبقى في متصفحك.

> **تنبيه أمني**: صفحة GitHub Pages عامة. حماية الرمز هنا «قفل باب» على الواجهة،
> وليست تشفيراً. الملفات المنشورة في المستودع (بما فيها `noor.db` و`uploads/`)
> يمكن تحميلها مباشرة من أي متصفح يعرف الرابط. لا ترفع سراً لا تحب أن تراه العامة.

## التشغيل (يوجد وضعان)

### الوضع 1 — سيرفر محلي بقاعدة بيانات في المجلد ⭐ (موصى به)
كل بياناتك تُحفظ تلقائياً داخل ملف **`noor.db`** في هذا المجلد نفسه، فيتحرك المجلد
كاملاً مع بياناته إلى أي جهاز. يكفي نقرة واحدة:

- **ويندوز**: انقر مزدوجاً على **`start.bat`**
- **ماك / لينكس**: شغّل `./start.sh` في الطرفية
- أو يدوياً: `node server.js`

يُفتح المتصفح تلقائياً على `http://127.0.0.1:4173/`. كل عملية (إضافة/إكمال/حذف)
تُحدّث قاعدة `noor.db` فوراً (مع نسخ احتياطية دورية في مجلد `backups/`).
للإيقاف: `Ctrl+C`.

> يتطلب **Node.js ≥ 22.5** (مثبّت مسبقاً لديك). لا حاجة لأي `npm install` —
> السيرفر صفري الاعتماديات ويستخدم وحدات Node المدمجة فقط.

### الوضع 2 — فتح مباشر (بلا سيرفر)
انقر مزدوجاً على **`index.html`** فيعمل فوراً عبر `localStorage` (بلا اتصال،
بلا تثبيت). لكن البيانات هنا داخل المتصفح لا داخل المجلد. يُكتشف غياب السيرفر
تلقائياً ويعمل التطبيق بسلاسة.

---

## أين تُحفظ البيانات؟

| الوضع | المكان |
|---|---|
| سيرفر محلي | ملف `noor.db` في المجلد + نسخ في `backups/` |
| فتح مباشر | `localStorage` داخل المتصفح |

في وضع السيرفر: بعد كل عملية تُدفع لقطة كاملة إلى `noor.db` (مع تأخير 1.5 ثانية
لتجميع التغييرات)، فقاعدة البيانات تتزامن مع أحدث حالتك دائماً.

## النسخ الاحتياطي والاستعادة

من **⚙ الإعدادات** داخل التطبيق:
- **↓ تحميل نسخة**: ينزّل ملف `noor-backup-YYYY-MM-DD.json` كاملاً.
- **استعادة**: تختار ملف نسخة فتُستبدل البيانات بمحتواه.

أنصح بتصدير نسخة أسبوعياً. في وضع السيرفر توجد أيضاً نسخ تلقائية في `backups/`.

## نقل المشروع لأي جهاز

انسخ المجلد كله (يشمل `noor.db`) إلى الجهاز الآخر، وتأكد من وجود Node ≥ 22.5،
ثم شغّل `start.bat`/`start.sh`. بياناتك تنتقل مع المجلد.

## هيكل المشروع

```
├─ index.html        نقطة الدخول (بوابة الرمز + الواجهة)
├─ js/lock.js        بوابة الدخول وحقن السكربتات بعد التحقق
├─ data/seed.json    البيانات المبدئية للنسخة المنشورة
├─ server.js         سيرفر محلي صفري الاعتماديات (node:http + node:sqlite)
├─ start.bat         تشغيل بنقرة واحدة (ويندوز)
├─ start.sh          تشغيل بنقرة واحدة (ماك/لينكس)
├─ package.json      (لا اعتماديات — فقط npm start اختياري)
├─ noor.db           قاعدة البيانات (تُنشأ تلقائياً)
├─ css/style.css     التصميم الكامل (عربي RTL)
├─ js/
│  ├─ store.js       طبقة البيانات (localStorage) + طبقة API محلية بديلة السيرفر
│  └─ app.js         الواجهة والتفاعل
├─ fonts/            خطوط محلية (Amiri + Tajawal)
├─ uploads/          المرفقات المرفوعة (صور/PDF)
└─ backups/          نسخ احتياطية تلقائية من قاعدة البيانات (غير مُرفع)
```

## النشر على GitHub Pages

النسخة المنشورة تعمل في **الوضع الثابت** (localStorage) بلا سيرفر:

1. المستودع عام إجبارياً — صفحات GitHub Pages لا تدعم المستودعات الخاصة.
2. عند الفتح، يكتشف `Bridge.detect()` غياب `/api/health` فيعمل التطبيق بسلاسة عبر
   `localStorage` (طبقة API محلية داخل `js/app.js`).
3. الروابط في `index.html` و`css/style.css` نسبية بالكامل، فتعمل تحت مسار فرعي
   `/<repo>/` بلا تعديل.

رابط النشر: `https://<username>.github.io/<repo>/`

## ملاحظات تقنية

- وضع `file://`: يكتشف التطبيق غياب السيرفر تلقائياً (`js/app.js` → `Bridge.detect`).
- الرفع: في وضع السيرفر يُحفظ على القرص في `uploads/`؛ وفي الفتح المباشر يُخزَّن
  كـ base64 داخل المتصفح (حتى 8MB).
- السيرفر يمنع اختراق المسار (path traversal) في الملفات والرفوعات.
- `apiFetch` في الوضع الثابت يسقط تلقائياً إلى المحاكاة المحلية (`_sendLocal`) عند
  غياب المسار في `_fetchLocal` — وهذا ما يُبقي صفحة المكتبة تعمل بلا خادم.
